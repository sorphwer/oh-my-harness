# Brainstorm Workflow

Phase: brainstorm

Entry criteria:
- New, ambiguous, or issue-driven work.

Exit criteria:
- A concrete behavior change or investigation target.
- The affected area is identified: exports, bindings, solving, CLI/config,
  errors, module resolution, state, tests, LSP, website, or VS Code extension.
- For GitHub issues, the live issue text is treated as the contract when
  available.

Checklist:
- Read the relevant local source before proposing a design.
- Prefer one failing or bug-capturing regression test for behavior changes.
- Clarify only when the repository context cannot resolve the ambiguity safely.
