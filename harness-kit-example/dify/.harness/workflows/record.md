# Record Workflow

Phase: record

Entry criteria:
- Change complete and review summary prepared.

Exit criteria:
- Change history updated when the harness, workflow, or durable project process
  changed.

Checklist:
- Keep entries short and rationale-focused.
- Do not record routine code changes unless the user or project process asks for
  it.
- Commit messages should explain why the change exists, the high-level approach,
  and why that approach works.
